# Task: host-owned cost-aware context projection

## Objective

Replace Orvek's late suffix truncation with one host-owned context system that lowers repeated model cost without losing authoritative history or stopping accepted work.

The durable host must own both source history and every derived model view. The system must keep stable prompt prefixes, support bitmap context carriers for eligible historical tool output, preserve exact byte retrieval, and select representations from measured provider cost.

## Definition of done

This task is complete when all of the following statements are true:

- The journal keeps immutable authoritative history. Applying a projection does not replace `SessionState::history`.
- Provider requests use stable, digest-addressed context segments and a small native working tail.
- Settled eligible tool output can use a durable bitmap representation generated by the host.
- Every bitmap page maps to exact source bytes that `read_context` can retrieve.
- Generated context images do not use the user-attachment limits in `crates/harness/src/input.rs`.
- Context conversion runs throughout a task. It does not wait for a fixed percentage of the configured window.
- Provider receipts record enough information to compare source text, the selected view, cache behavior, output tax, and total dollars.
- A renderer or profile failure falls back to native text for that segment and does not stop the task.
- Orvek adds no spend limit, call limit, forced task stop, or smaller context-window policy as part of this work.
- Paired evaluations report task quality, exact retrieval, total cost, output and reasoning tokens, latency, and warm and cold cache behavior for Sol, Terra, and Luna.
- The full test, lint, format, documentation, and codebase-graph checks pass.

The baseline comes from `~/.orvek/host/v1/v1.sqlite3` through 2026-09-19 14:42 UTC.

The 243 non-null provider-cost receipts total `$58.4698716`. Matched task-model usage accounts for `$58.4155516`:

| Uncached input | `$33.8609760` |
| Cached input | `$17.8261356` |

The same task calls would cost about `$218.8507720` without prompt caching. Provider caching saved about `$160.4352204`. Current context projection saved `$0` because no projection occurred.

A cache-structure estimate found 7,262,623 previously existing input tokens that did not receive the cached rate. Their estimated extra cost is `$26.1454428`. The largest exact request cost `$20.792`; about `$12.108` came from this repeated uncached input estimate.

Older provider receipts include 431 null costs. Using current catalog rates, all observed usage is valued at about `$323.5394328`, compared with `$1,447.7343540` without caching. Treat these older totals as estimates, not authoritative billing.

One Terra session reported 1,316,154 input tokens despite a configured 1,000,000-token window. Its final serialized history used about 1.38 bytes per reported token. Other inspected sessions used 1.3 to 1.6 bytes per token. The current four-bytes-per-token assumption is not conservative for these code-heavy histories.

## Baseline behavior replaced by this plan

The pre-plan audit found these properties:

- `crates/harness/src/context.rs` started automatic projection at 85% of the configured window.
- It converted tokens to bytes with a fixed four-bytes-per-token estimate.
- `project` removed whole oldest history items until the remaining JSON suffix fit.
- The replacement was a developer message that stated that records were omitted. No summary or alternate carrier replaced their contents.
- `crates/harness/src/session.rs` applied `ContextProjected` by replacing `SessionState::history`.
- `crates/harness/src/controller.rs` persisted a projection only when it omitted items or repaired interrupted calls.
- `InferenceRequest::with_prompt_cache_key` routed a session to one provider cache key, but the host did not model immutable cache segments.
- `read_context` returned at most 24 KiB and could not return a slice of one oversized history record.
- `input::materialize` applied user-image limits and replaced older images with text placeholders after 4 MiB.

Commit `ccd08d8` removed the previous terminal-owned SnapCompact renderer and archive when context ownership moved into the durable host. Do not restore that ownership split. Move the useful renderer, archive, and retrieval behavior under `orvek-harness`.

## SnapCompact evidence and limits

Stencil reports that SnapCompact reduced 170K carried text tokens to 46K image tokens, a 3.7x reduction. Its total-cost results were model-specific:

- Claude configurations approached 2x total-cost savings at similar quality.
- GPT-5.5 moved from `$0.34` to `$0.19`, a 1.8x reduction, but lost 12 F1 points.
- Dense images increased reasoning output because models had to decode the text.

Applying those ratios to Orvek is only a counterfactual:

- Applying 1.8x to the exact `$58.4155516` task sample gives `$32.4530842`.
- Dividing all input cost by 3.7 while keeping output cost unchanged gives `$20.6979296`.

The second number is an optimistic ceiling. It assumes every input token is eligible, the cache mix stays unchanged, and bitmap decoding adds no output. Implementation decisions must use Orvek measurements rather than these transferred ratios.

## Required design

### Keep source history separate from model views

The journal and session projection must retain the full authoritative history. A model view is derived data and has its own manifest.

Use explicit types for source ranges and representations. The exact names can change during implementation, but the domain must express these states:

```rust
enum ContextRepresentation {
    NativeText,
    Bitmap(BitmapManifest),
}

struct ContextSegment {
    source: HistoryRange,
    source_digest: Digest,
    representation: ContextRepresentation,
}

struct ContextView {
    source: SessionCursor,
    segments: Vec<ContextSegment>,
    live_tail_start: usize,
}
```

A projection command records the selected `ContextView`. It must not mutate or delete source history.

### Keep the provider prefix stable

Build each request in this order:

1. Stable control instructions and tool definitions.
2. Stable historical segments in source order.
3. The recent native working tail.
4. The current user input.

Once the host publishes a segment, it must not rerender or reorder that segment unless its source digest or renderer profile changes. Append new segments after settled work. Derive prompt-cache lineage from stable segment and instruction digests rather than using only the session ID.

### Convert historical output continuously

Do not use a fixed 85% trigger.

After a successful tool result has been consumed by a later model response, the host can seal it as a historical segment. The host should render eligible text in the background and use the page artifacts on later calls. Keep current instructions, user messages, tool calls, failed or pending results, native media, and the recent working tail as native protocol items.

Keep both native text and bitmap artifacts. If the selected model has no usable bitmap profile or rendering fails, send native text for that segment and continue.

### Store generated context media as internal artifacts

Generated pages need a path separate from user-submitted images.

Each page record must include:

- Source session and revision.
- Source item and content index.
- Start and end byte offsets.
- Source digest.
- Renderer profile and version.
- Page digest, dimensions, and media type.
- Stable provider serialization data when the provider supports reusable files.

Do not apply the user-input limits of eight images and 4 MiB to internal context pages. Do not silently replace generated pages with placeholders.

### Support exact retrieval

Extend `read_context` so the model can retrieve the exact source behind a page:

- Source session and revision.
- History item.
- Content index or JSON path.
- Byte offset and byte length.
- Optional literal search.
- Original and model-visible source when they differ.
- A continuation offset.

Retrieval must return a bounded slice of an oversized record instead of rejecting the whole record. A test must reconstruct a large archived value byte for byte through multiple calls.

### Select representations from measured cost

The selector must compare native text and bitmap forms for each segment. It must include:

- Model and renderer profile.
- Measured text and image input tokens.
- Cached and uncached input rates.
- Observed cache hits for the stable prefix.
- Expected future uses of the segment.
- Additional output or reasoning tokens caused by bitmap decoding.
- Retrieval calls and their cost.

Provider receipts must update these observations after each call. Do not use serialized bytes as the final token estimate. If the provider has no token-count endpoint, calibrate a model-specific estimator from actual usage deltas and record its error.

This selection changes representation only. It must not impose a dollar budget, call budget, or task stop.

## Required regressions

Add tests for these cases:

- Projection does not mutate authoritative history.
- A 1.3-bytes-per-token fixture does not rely on the old four-byte estimate.
- Consecutive requests preserve an identical stable prefix.
- A large result changes from native text to pages after its first use.
- A bitmap page survives restart and retains the same digest.
- Exact retrieval reconstructs an oversized record.
- A fork cannot read records outside its inherited cutoff.
- Corrupt page data falls back to native source text.
- Unsupported Unicode remains native unless the active profile supports it.
- Pending and failed tool outputs remain native.
- Internal pages bypass user-image limits without weakening user-image validation.
- Null or conflicting provider costs remain unknown.
- Provider-reported cost wins over catalog pricing.
- Diagnostics report zero representation savings when no representation changed.
- Rendering failure does not settle or stop the active task.

## Explicit non-goals

This task does not:

- Add a spending budget.
- Limit the number of model or tool calls.
- Stop accepted work because a cost estimate is high.
- Shrink the configured context window to hide repeated input cost.
- Move context ownership back into the TUI.
- Trust summaries as a replacement for exact history.
- Apply user-attachment policy to host-generated context pages.
- Claim SnapCompact savings before paired Orvek evaluations measure them.
